# Запуск DragAPI на сервере

По умолчанию платформа слушает только `127.0.0.1`, то есть открыта лишь на той машине, где запущена.
Чтобы с ней работали с других компьютеров, выберите один из трёх вариантов.

| Вариант | Когда подходит | Сертификат |
|---|---|---|
| **A. Прокси (Caddy / nginx)** | Есть домен, сервер в интернете | Let's Encrypt, бесплатно и автоматически |
| **B. Свой HTTPS платформы** | Офис или домашняя сеть, домена нет | Платформа выпускает сама; браузерам можно доверить её CA |
| **C. Свой сертификат** | Сертификат уже есть, прокси не нужен | Ваш |

Во всех вариантах **вход в платформу обязателен.** С `--no-auth` на внешнем адресе или за прокси сервер
откажется запускаться. При первом входе платформа предложит создать администратора.

## Подготовка

```bash
git clone <репозиторий> dragapi && cd dragapi
./start.sh setup          # Python-окружение и npm-пакеты (нужны Python 3.10+ и Node.js 18+)
```

Код пользователей платформа выполняет в песочнице. На сервере лучше поставить firejail
(`sudo apt install firejail`). Для кнопки «Деплой» API-проектов нужен Docker, и пользователь службы
должен входить в группу `docker`.

## A. Домен + Caddy (рекомендуется)

1. DNS-запись домена указывает на сервер, порты 80 и 443 открыты.
2. Платформа — служба systemd, слушает только 127.0.0.1:

   ```bash
   deploy/install-service.sh --proxy
   ```

3. Caddy (`sudo apt install caddy`): впишите свой домен в [Caddyfile](Caddyfile), положите файл в
   `/etc/caddy/Caddyfile` и выполните `sudo systemctl reload caddy`. Сертификат Caddy получит и
   продлит сам.

**nginx вместо Caddy:** возьмите [nginx.conf](nginx.conf) и выпустите сертификат через
`sudo certbot --nginx -d ваш.домен`. В конфиге уже есть вебсокеты агентов, долгие таймауты для вебхуков
и лимит загрузки 25 МБ.

Платформа верит заголовкам `X-Forwarded-Proto` / `X-Forwarded-For` только от `trusted_proxies`
(по умолчанию `127.0.0.1`). Если прокси стоит на другой машине, впишите её адрес в `backend/dragapi.toml`.

## B. Локальная сеть, свой HTTPS

```bash
deploy/install-service.sh --self-signed       # служба: https://<IP сервера>:8765
# или без службы:
./start.sh --host 0.0.0.0 --tls-self-signed
```

При первом запуске платформа создаёт в `backend/data/tls/` свой центр сертификации (`ca.pem`, 10 лет) и
сертификат сервера. В сертификат попадают имя машины, `localhost` и все её IP-адреса. Дополнительные имена
задаются через `tls_names = ["dragapi.lan"]` в `dragapi.toml`. Если адрес сервера сменится, сертификат
перевыпустится сам, а CA останется прежним.

- **Браузер** сначала предупредит о неизвестном сертификате. Чтобы предупреждение исчезло, добавьте
  `backend/data/tls/ca.pem` в доверенные корневые сертификаты:
  - Windows: двойной клик → «Установить сертификат» → «Доверенные корневые центры сертификации»;
  - macOS: «Связка ключей» → «Всегда доверять»;
  - Linux / Chrome: «Настройки → Безопасность → Управление сертификатами → Центры сертификации → Импорт».

  Отпечаток CA сервер печатает при запуске: сверьте его перед установкой.
- **Удалённые агенты** скачивают zip в окне «🖥 Агенты». Файл `platform-ca.pem` уже лежит в zip, и агент
  подхватывает его сам. Запуск: `--server https://<IP>:8765`.

## C. Свой сертификат без прокси

```bash
./start.sh --host 0.0.0.0 --port 443 --tls-cert /path/fullchain.pem --tls-key /path/privkey.pem
```

То же можно записать в `backend/dragapi.toml` (`tls_cert`, `tls_key`). Порты ниже 1024 (в том числе 443)
обычному пользователю недоступны. Оставьте порт 8765 (`https://домен:8765`) или используйте прокси
(вариант A): запускать платформу от root не нужно.

## Служба systemd

`deploy/install-service.sh` делает следующее:
1. ставит зависимости;
2. собирает интерфейс;
3. записывает `/etc/systemd/system/dragapi.service` от имени текущего пользователя;
4. включает автозапуск.

```bash
deploy/install-service.sh --proxy | --self-signed | --local  [--port 8765]
deploy/install-service.sh --print --proxy     # только показать службу
deploy/install-service.sh --uninstall         # убрать службу (данные не трогает)

journalctl -u dragapi -f                      # журнал
sudo systemctl restart dragapi                # перезапуск
```

Служба запускается с `DRAGAPI_LOCAL_AGENT=off`, потому что у сервера обычно нет экрана. Сценарии
автоматизации выполняют удалённые агенты. **Обновление:** `git pull`, затем снова
`deploy/install-service.sh --<режим>`. Скрипт пересоберёт интерфейс и перезапустит службу.

## Резервная копия

Всё состояние платформы лежит в `backend/data/` (или в `DRAGAPI_DATA_DIR`): проекты, история, пользователи,
базы, сертификаты. Особенно важен `data/secret.key`: без него не расшифровать секреты проектов.
